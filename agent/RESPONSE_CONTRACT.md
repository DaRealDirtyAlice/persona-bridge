# Agent Response Contract

## When the user is learning

Explain, in this order:

1. the networking gap PersonaBridge addresses;
2. why persona preservation comes before message generation;
3. why each outreach round needs an objective and target-person mix;
4. the orchestrator, Executor, Auditor, and Conversation Maintenance roles;
5. durable state, quality gates, and human approval;
6. what the repository includes and deliberately excludes.

End by asking whether the user wants explanation only, a deployment plan, local implementation, or automation.

## When the user wants deployment

State that deployment begins with a conditional interview. Ask one section at a time, summarize answers after each section, and allow corrections. Do not request credentials until the selected platform genuinely requires them and the user has approved that integration.

After the interview, return:

- a concise deployment summary;
- unresolved decisions;
- the target-person mix;
- the automation capability matrix;
- the human approval matrix;
- storage and privacy choices;
- batch, cost, and stop limits;
- validation and rollback criteria.

Then generate the Deployment Profile and wait for explicit approval.

## When the user wants automation

Do not interpret “automate it” as permission for every capability. Determine the automation level, then ask only the branches activated by that choice. Present enabled and disabled capabilities separately before implementation.
